Layer 1 — data sources. These are external services you don't control. GitHub, Google Calendar, Jira, your VS Code editor, Slack. They all have APIs — basically URLs you can call to get data. Your job is to call them and pull the data into your own system.
Layer 2 — OAuth token manager. Before you can call GitHub's API on behalf of a user, you need their permission. OAuth is the standard way this works — user clicks "connect GitHub", gets redirected to GitHub, approves access, and GitHub sends you a token. Your token manager stores that token and uses it for all future API calls. It also handles polling (calling the API every 15 minutes to check for new commits) and webhooks (GitHub calling you instantly when something happens).
Layer 3 — BullMQ + Redis. You can't call GitHub's API in real time every time a user opens the dashboard — too slow, and GitHub will rate-limit you. Instead you run background jobs. BullMQ is a job queue: you add a job ("sync GitHub for user X"), and a worker picks it up and runs it in the background. Redis is where BullMQ stores these jobs — it's an in-memory database, extremely fast.
Layer 4 — core backend services. Three services, each with one responsibility. The activity service takes raw GitHub events (a commit happened, a PR was opened) and normalises them into a consistent format. The metrics service crunches those events into useful numbers (you coded 3.5 hours today, your flow score is 72). The AI insight service takes those metrics and sends them to Claude API to generate human-readable insights like "your best focus window is 9–11am".
Layer 5 — storage. Three databases, each chosen for what it's best at. PostgreSQL stores structured data that doesn't change much — your user profile, OAuth tokens, goals. TimescaleDB (which is PostgreSQL with a plugin) is optimised for time-series data — thousands of rows of "at 10:32am you made a keystroke" queries very fast. Redis stores sessions (is this user logged in?), the job queue, and cached API responses.
Layer 6 — frontend. Next.js 14 app that calls your Express API and renders the data. Recharts draws the charts. Zustand manages UI state. Tailwind handles styling. tRPC is a type-safe way to call your API (we'll explain this when we get there).
